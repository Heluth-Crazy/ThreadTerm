# ThreadTerm · 消费级应用原型（改造版）

> 本目录是 `prototype/threadterm-product-vision/` 的**独立重构版**。
> 原原型保留不动、不改名。本目录从零搭建，不复用其代码文件，但**沿用同一套演示数据与中文文案**（从旧版 `app.js` 移植），保证两版可直接对比。

## 定位

参照系：Codex App / Linear / Warp 级别的成熟消费级 PC 应用，而非个人 vibe 产品。
相对 Codex App 的增强点（本产品的卖点，必须突出）：

1. 多 agent（Claude / Codex / Gemini / Shell）
2. 侧栏项目树支持 **worktree 级**，且每个 worktree 带状态
3. 状态感知：一眼看出哪些会话**处理中 / 需要你 / 需要关注**

## 硬约束

- **不删任何功能**。只允许：调整位置、调整层级、调整 UI 呈现。
- 纯静态、无构建：`index.html` + `styles.css` + `app.js`，双击或任意静态服务器可跑。
- 所有交互为本地演示，不执行真实命令；底部状态栏常驻标注 `离线运行 · 不连接真实终端`。
- 深色为主主题，保留浅色 token（`data-theme="light"`）。
- 可及性：`aria-live` 播报区、`.sr-only`、键盘 Esc 关闭浮层、Ctrl+K 命令面板。

## 设计 token（在旧版基础上收敛）

- 色板沿用旧版深色：`--bg:#101214 / --side:#141719 / --surface:#191d20 / --raised:#202629 / --soft:#252c30 / --border:#30373b / --text:#eef2f1 / --muted:#aeb9b5 / --faint:#97a5a0`，强调色仅薄荷 `--mint:#83e1c2`。
- **状态五态，全产品统一**（旧版 8 态保留为详情页二级信息）：
  - `需要你` = 琥珀 `#f3c781`（待确认/待输入/待复核/需要输入 都归入此态）
  - `运行中` = 薄荷 `#83e1c2`
  - `失败` = 红 `#ff9c9c`
  - `已结束` = 灰 `#97a5a0`（已完成/已停止）
  - `停滞` = 蓝 `#8db7ff`（目录缺失/长时间无输出等提示性状态）
- 间距刻度只用：4 / 8 / 12 / 16 / 20 / 24 / 32 / 48。
- 字号层级 ≤ 5 级：12（辅助）/ 13（正文小）/ 14（正文）/ 16（卡标题）/ 20（页标题，半粗）。
- **页标题是功能性的**（"工作台""待处理"），禁止营销式大标语。营销文案只允许出现在空状态或 Local Pro 页。
- 圆角统一 11px，卡片可 12px；阴影轻而弥散。
- 次要文字优先用 `--muted`，避免在深色底上用 `--faint` 放小字（对比度不足）。

## 信息架构

### 侧栏（240px，固定）

- 工作区导航（单行图标项）：
  - `工作台`
  - `待处理` —— **右侧常驻计数徽章（琥珀底）**，全局唯一队列入口
  - `所有终端`
  - `历史记录`
  - `工作预设`
- 项目树（核心卖点区）：
  - 项目行：`▸/▾` + 状态点 + 项目名 + 折叠时右对齐**汇总徽章**（该项目下"需要你"的会话数）
  - worktree 行：**单行** = 状态点 + 分支名 + 右侧计数徽章；选中态左侧 2px 薄荷竖条
  - 每个 worktree 只占一行，状态细节（如"需要输入 · 2 会话"）收进 title 提示或详情，不折行
- 底部：`设置` 图标行 + `Local Pro` 一行文字链接（不再是一级导航，不再有描边营销卡）

### 顶栏（52px）

- 左：当前位置（面包屑，仅一段，如 `工作台` / `orbit-web · 工作区`）
- 中右：**唯一命令入口** `搜索命令、项目、会话，或切换终端…  Ctrl K`（合并旧版"搜索框 + 切换终端"两个控件）
- 右：`+ 新建终端`（薄荷主按钮）、通知铃铛（带计数点）、设置齿轮
- 不再有每页右上角的"体验场景/体验浮窗"按钮（演示控制移到底部状态栏）

### 底部状态栏（24px，弱化）

- 左：`演示数据 ▾`（场景切换，收起在状态栏里）、`交互原型` 标注
- 右：`离线运行 · 不连接真实终端 · 2026.09`

## 补充：功能基线补齐（对照旧版 feature-parity.zh-CN.md）

第一版实现漏掉了以下能力，必须补齐，呈现方式按本节新规执行：

### 9. 浮动终端（真浮层，不是 toast）

- `在浮窗打开`（所有终端卡片 ⋯ 菜单、工作区、命令面板）打开**页面内浮动终端层**：标题（会话名 + 项目·分支）、状态与目录、输出区、输入条（草稿独立保存、已结束会话禁用输入）、操作行（关注/已关注、置顶演示、收起、回主窗口、结束会话）。
- 收起后状态栏旁出现 `恢复浮窗 · <会话名>` 按钮；置顶为演示态（toast 说明"这不是系统窗口"）。
- 结束会话走确认对话框（目标、目录、"不会关闭真实终端"说明），确认后会话变"已结束"，浮窗随之关闭，历史仍可查看。

### 10. 项目总览 / 工作树概览（恢复作用域导航）

- 侧栏交互：项目行 chevron 负责展开/收起，**点项目名 → 项目总览**；**点 worktree 行 → 工作树概览**。会话级入口（最近会话、待处理行、终端卡片）仍直达工作区。
- 项目总览（`#/project/<id>`）：项目状态与路径、`新建终端`（预选本项目）、**本项目范围的待处理列表**与**重点关注列表**、项目内会话清单、`新建工作树` 入口。
- 工作树概览（`#/worktree/<id>`）：分支/目录/当前状态/继续位置、`继续工作` 与 `新建终端`（预选该树）、**该树范围的待处理与关注**、该树会话清单、`移除工作树`（主工作树与受保护树给出"不能移除"原因对话框；有运行中会话/未保存草稿/未提交差异时同样拦截并说明）。
- 两处概览页是本产品相对 Codex App 的"作用域状态感知"卖点，排版保持行式列表密度，不做成营销页。

### 11. 重点关注的管理能力

- 重点关注标题旁 `添加关注`：对话框内搜索 + 多选终端 + 确认；取消不改变现有集合。
- 关注项支持 `重命名`：同一会话在所有入口同步显示新名称，名称不改变会话/工作树身份。
- 已结束/目录缺失的关注项保留：可读历史，不直接输入。

### 12. 首次启动欢迎页

- 营销文案的正式归宿。首次访问（localStorage 无标记）显示一次欢迎浮层：产品名 + "从上次停下的地方继续。"定位语 + 三条卖点（多 agent / worktree 树与状态 / 待处理与关注）+ `开始体验`；`演示数据 ▾` 菜单里提供"首次启动引导"随时重看。

## v3 方向：与 Codex/ChatGPT 桌面版设计语言融合（最高优先级，与上文冲突时以本节为准）

参照物：ChatGPT/Codex 桌面版（暖米色、无框、侧栏主导、主区居中极简）。它的短板正是我们的卖点：不支持 worktree、无会话总览、无状态感知。融合 = 它的壳与气质 + 本规格的功能与 IA。功能清单不变（不删任何功能），变化的是壳、配色、布局与控件形态。

### 视觉 token（替换"设计 token"一节的配色部分；状态五色语义不变）

- **默认主题为暖米浅色**：`--bg:#f6f3ec`（主区）、`--side:#efece2`（侧栏）、`--surface:#fdfcf8`（卡片/浮层）、`--border:#e4dfd2`（细发丝线，尽量不用）、`--text:#2c2a24`、`--muted:#716b5d`、`--faint:#8f887a`。
- 深色主题保留但改为**暖调炭黑**：`--bg:#1b1a16`、`--side:#201f1a`、`--surface:#26251f`、`--border:#38362e`、`--text:#ece8de`、`--muted:#a39c8d`。
- **主按钮从薄荷改为墨色**（浅色主题下近黑 `#2c2a24` 底白字，参考 ChatGPT 发送钮）；薄荷只保留给"运行中"状态语义与极少量品牌点缀。
- **去边框化**：用底色差分层，卡片尽量无 border，只有浮层/对话框用 `0 18px 55px #2c2a2414` 这类暖色软阴影。
- 圆角放大：列表项/按钮 8–10px，卡片 14px，composer/对话框 18–20px。
- 字号层级不变（12/13/14/16/20），但整体观感更安静：侧栏 13px，页标题 20px 半粗，不用粗黑标题。

### 壳：取消全局顶栏，侧栏承载一切（替换"信息架构"的顶栏部分）

- **没有横跨窗口的顶栏**。窗口即侧栏 + 内容区。
- 侧栏自上而下：
  - 品牌行：`ThreadTerm` 标识 + 右侧搜索图标（开命令面板，Ctrl+K 不变）与通知铃铛（带计数点）
  - 导航项：`新建终端`（等同 ChatGPT 的"新对话"，行内加号图标）、`待处理`（徽章）、`所有终端`、`历史记录`、`工作预设`
  - `项目` 分区：**三级树** = 项目文件夹 → worktree（状态点 + 计数徽章，单行）→ 会话（状态点 + 名称，单行）。chevron 管展开收起；点项目名进项目总览，点 worktree 进工作树概览，点会话直达工作区。
  - `最近` 分区：最近会话平铺（单行）
  - 底部：用户行（头像 + 本地用户），点击弹出菜单（设置、外观切换、Local Pro、关于）。侧栏不再有独立 Local Pro 导航项。
- 底部状态栏保留（演示标注用），但视觉再弱一档，近乎隐形。

### 工作台 → 居中起始页（替换原"工作台"视图布局）

- 内容居中窄列（约 720px），自上而下：
  - 平静的大问句，如 `从哪开始？`（允许这一句——它是起始页而非营销页）
  - **Composer 式创建框**（全宽、大圆角、软阴影，参考截图）：占位文案"描述要开的会话，或直接选项目开始…"；框内左下 chip 行：`项目 ▸`、`Worktree ▸`、`Agent ▸`（参考截图里"学习计划/插件"chip 形态）；右下墨色圆形发送钮。回车/点击 → 打开新建终端对话框（预选已填），不直接执行。
  - `继续上次`：一行安静的横条（会话名 + 项目·分支 + 状态 chip + 继续按钮）
  - `待处理`速览：N 项需要你 · M 项失败 + 查看全部
  - `最近会话`：安静行式列表
- 你的项目卡片网格、Local Pro 提示条**不在起始页**——项目从侧栏进，Pro 入口在用户菜单。

## v9 修订：侧栏状态动效（最高优先级，与上文冲突时以本节为准）

- **运行中（绿）**：状态点本体呼吸——透明度/缩放缓慢脉动（约 2.4s ease-in-out 循环，opacity 1→0.45→1，scale 1→1.15→1），只动点本体。

- **两者同时满足**：绿芯呼吸 + 琥珀环扩散，叠加呈现；禁止用同一属性同时表达两种状态（如不许颜色来回切、不许呼吸环二合一）。

- 工作区会话 chip、终端卡片等其它位置的状态点不动（仅侧栏树）。

## v16 修订：分支/项目主页区块固定渲染，结构不随数据有无变化（最高优先级，与上文冲突时以本节为准）

问题确认：分支主页的「需要关注」「运行中的会话」等区块在无数据时整块收起，导致像 main 这样的分支页只剩时间线和用量——用户看到的就是"区块被去掉了"。这违背了一贯原则：**固定布局，内容有无不影响布局变化**。

### 改法

- 分支主页与项目主页的**所有简报区块固定渲染、不再收起**：页头 / 指标条（带 sparkline）/ 需要关注 / 运行中的会话（项目页为"运行中的工作树"）/ 最近活动 / 用量面板（分支页"本分支用量"，项目页"本项目用量"）。
- 区块无数据时**保留标题与区块框架**，内容区显示一行小字空态（slate 色 12-13px），例如：
  - 需要关注 → "暂无需要关注的事项"
  - 运行中的会话 → "暂无运行中的会话"
  - 最近活动 → "暂无活动记录"
  - 本分支用量（无会话时）→ "暂无用量的会话"
- 项目页同样改为固定渲染 + 一行空态（覆盖 v12 的"整块收起"写法），两层完全同构：分支页相对项目页**只有两处粒度替换**——"运行中的工作树"→"运行中的会话"、"本项目用量"→"本分支用量（按会话拆分）"，其余结构与呈现一律不动。
- 分支页指标条保持 4 项（分支层没有"工作树数"维度），但样式、sparkline、顺序与项目页一致。
- 之前的"关注为空"演示开关保留（用于演示空态），但空态表现从"收起"改为"一行小字"。
- Linear 质感、深浅主题不变；空态行要安静克制，不是大空态插画。

### 验收（v16）

- main 分支页（无运行中/无待处理）：指标条、需要关注、运行中的会话、最近活动、本分支用量**五个区块全部可见**，空区块为一行小字空态
- checkout-a11y 分支页：有数据时与 v15 呈现一致；项目页同法固定渲染
- 切换"关注为空"演示开关：区块不消失，显示一行空态
