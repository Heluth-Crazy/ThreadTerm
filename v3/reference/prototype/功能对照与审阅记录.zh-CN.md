# ThreadTerm 功能对照与审阅记录

> **版本与范围**：2026-09-08，只读静态审阅；同日 v3 原型去掉「下载 AI Markdown」。本文把现有主应用、当前可点原型和原始原型说明书逐项对照，供产品评审使用；没有启动桌面应用、真实终端、CLI、移动设备或浏览器交互。VS Code 扩展不在本次功能清单中，也不表示弃用。
>
> **怎样审阅**：先看每行的“处理/目标需求”，再用“当前状态”判断它是已接入、待接通还是仅演示。`保留` 表示已纳入需求讨论，并不等于已经实施或已经确定首版；`待评审` 表示不能由本次文档替用户决定。源码链接均从本文件相对定位，`Lxx` 是本次静态审阅的定位线。出现测试文件不作为本次运行通过的证据。

## 读法、状态与证据置信度

| 字段 | 含义 |
| --- | --- |
| 出处 | `现有`＝主应用源码；`原型`＝当前离线原型/原稿；`两者`＝两边都有相关表达；`历史`＝旧资料线索。 |
| 当前状态 | `已接入`＝源码存在用户路径；`部分/未接通`＝有界面、协议或服务但当前主路径不能完整使用；`仅原型`＝合成离线演示；`未查到`＝本轮未找到已接线实现。均非运行测试结论。 |
| 原型覆盖 | `完整`、`部分`、`未涉及`、`演示限制` 或 `本轮明确去掉`；原型缺席不构成删除决定，`本轮明确去掉` 才是原型演示范围的明确收缩。 |
| 证据置信度 | `高`＝直接源码定位；`中`＝现有与原型资料相互印证；`低`＝历史线索或需用户选择。 |

- 没有以静态源码替代真实运行验证；尤其移动桥接、通知、终端执行和系统浮窗仍须在后续验收场景中实测。
