# ThreadTerm V3 approved production scope

Windows-first Electron + React/TypeScript and an independent Rust daemon, developed on feat/v3-electron-rebuild. Latest reference/prototype is the visual and interaction reference, never a source of production mock data. Fresh V3 data namespace; no V2 import. All five providers (Codex, Claude Code, Kimi, Gemini, OpenCode) need real Terminal and structured Chat, native history discovery and eligible resume. Shell/Grok/custom executable terminals remain supported. Mode is selected on creation, no live mode conversion promise.

Complete projects/worktrees, all-terminals history/detail rail, attention inbox, followed/recent items, search, daily CodeMirror editing and conflict-safe drafts, Git status/diff/actions, Markdown/HTML previews, four-pane workspaces, independent windows, themes/language/shortcuts, data backup/relocation, desktop device pairing/permissions, terminal-host MCP and genuine usage statistics. Remove AI Markdown download and all Local/Pro purchasing/trials. Phone UI and VS Code extension deferred; no LSP requirement.

Closing main window continues in tray; renderer/main crashes must not kill runtime work. Explicit quit with running tasks asks before termination. Runtime crash recovers persisted state and marks jobs interrupted, never blindly repeats commands. Native provider history remains discoverable despite no V2 migration.

Acceptance: actual Windows Electron app and installer; light/dark at 1280/1440/1920; real PTY I/O/resize/reconnect; all five real Chat adapters and histories; duplicate-native-owner rejection; approval fencing; renderer/main crash recovery; drafts/IME/undo/conflict; runtime, TypeScript and integration checks; no fake success when CLI/auth unavailable. Missing environment requirements must be reported accurately.

Agent browser preview bindings are approved: bundled Codex plus opt-in user bindings for supported MCP-capable Chat adapters. Core tools present credential-free loopback HTTP(S) pages and report observed state, without claiming application readiness or content verification. New pages reuse browser panes through rounded theme-aware page tabs; ownership-aware comments permit confirmed cross-agent draft transfer. Full browser automation, terminal integration and broader URL access are deferred.

Chat parity with codeg (approved 2026-10-11). The Chat surface gains codeg's most useful abilities for every provider: typed tool cards with a per-turn summary and an agent plan panel; one chip per composer setting with On/Off toggles, model search and a combined model-plus-thinking chip; a context ring and connection chip; one-click copy for replies and code blocks; a plan approval card; a diff preview inside edit approvals; files changed per reply with a turn footer; message navigation; quick messages with a `+` add menu and file attach; a selection bubble offering Copy, Quote and Ask; Mermaid, math and JSON-tree rendering; a background task strip with Stop; Markdown export; and generated UI cards and charts at P3. Steering into a running turn is native on Claude, Codex and Pi and falls back to a feedback note elsewhere. Agents additionally get ThreadTerm's own Ask, Feedback and Session-info tools, all enabled by default, plus delegation with its own switch. Mentions cover files, sessions, commits, agents and skills, delivered now as context-tray chips, with inline badges evaluated later. Every fork creates a new sidebar session. Pi's project-trust banner explains skipped project resources and records the user's decision in ThreadTerm. Out of scope: codeg's office and science quick actions, pets, chat channels and shareable usage card; browser and computer-use agent tools, automations and the to-do board; a rich-text editor rewrite; HTML or image export; Session Details, Tags, the Token Usage page and global search changes; and app-hosted tools for Pi.
