# 终端输出处理性能与无损保护

## Goal

大输出时减少重复计算和内存积压，同时保证终端文字、颜色、光标控制和恢复画面不被破坏。

## Requirements

- “最近输出摘要”不得对即将丢弃的大段历史反复执行完整文本清洗。
- 优化必须正确处理跨输出块拆开的颜色/控制指令，不能先任意截断原始字节。
- 后台预览继续接收每段输出，但每个刷新周期最多读取一次完整屏幕。
- 快速刷新路径不得对同一积压内容重复执行全量清洗。
- 快照失败期间的后台积压必须有内存上限。
- 达到上限时不得静默丢弃；必须记录缺口并在恢复后请求权威快照。
- 所有输出序号缺口都有计数、日志和可恢复路径。

## Acceptance Criteria

- [ ] 100 MiB 输出下摘要和预览 CPU 时间显著下降。
- [ ] ANSI/TUI 跨块 fixture 与优化前画面一致。
- [ ] 快照连续失败时后台内存保持在设定上限。
- [ ] 恢复后画面来自权威快照，不显示伪造的连续输出。
- [ ] 正常输出路径无新增丢字、乱码或光标异常。
