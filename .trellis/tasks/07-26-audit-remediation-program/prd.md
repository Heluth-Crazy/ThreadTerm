# 项目审查整改总计划

## Goal

除“限制文件浏览范围”外，完整实施 2026-07-26 全面审查中确认有价值的整改，让手机连接可信、终端任务不中断、局域网访问可控、界面稳定，并把本地测试变成持续门禁。

## User Decisions

- 文件浏览范围保持现状，不增加“只能浏览已添加项目”的限制。
- 手机断线应在 15 秒内被识别。
- 电脑端重启后，手机自动重新取得当前状态。
- 权限被撤销后，手机停止重连并明确说明原因。
- 持续输出时，手机最迟 1 秒获得一次最新状态。
- 手机旧输出达到上限后保留最近内容，并显示“更早内容已省略”。
- 局域网访问必须由用户明确开启；默认只允许本机访问。
- 手机输入优先于操作记录；记录失败必须可见、可统计。
- 由 ThreadTerm 管理的子进程随 ThreadTerm 退出，不留孤儿进程。
- 运行中的任务卡位置稳定，不随每次输出跳动。

## Explicit Exclusion

- 不改变文件浏览授权范围。
- 不采用静默丢终端内容、粗暴截断控制序列、盲目升级依赖等被审查判定为不安全的“优化”。

## Task Map

| 子任务 | 用户价值 |
|---|---|
| `audit-safe-remediation` | 已完成后台黑框、依赖固定、最小 CI 和测试稳定性基础 |
| `mobile-connection-lifecycle` | 断线、撤权、回前台时给出可信连接状态并自动恢复 |
| `mobile-output-sync-memory` | 电脑重启后不冻结、输出不缺段、内存有上限 |
| `lan-security-exposure` | 局域网明确开启，终端内容与凭证不明文裸奔 |
| `terminal-runtime-reliability` | 输入不卡顿、最小化不拖停任务、退出不残留进程 |
| `backend-background-io` | 网络探测和大型会话目录不再卡界面 |
| `frontend-stability-performance` | 卡片不跳位，无关界面不重复刷新 |
| `terminal-output-performance` | 大输出减少无效计算，同时保证内容无损 |
| `architecture-cleanup` | 大模块可维护，废弃代码不继续干扰新功能 |
| `reliability-test-gates` | 真实断连、多任务和最小化场景成为自动门禁 |

## Acceptance Criteria

- [ ] 每个子任务都有独立 PRD、设计、实施清单和验证结果。
- [ ] 子任务按依赖顺序实施，不在一个提交边界混入无关功能。
- [ ] 所有功能改动兼容已保存数据；需要协议升级时保留明确版本错误和恢复路径。
- [ ] Windows、桌面前端、移动前端和 Rust 后端门禁全部通过。
- [ ] 每一阶段只暂存，不推送；提交动作继续服从用户单独指令。
