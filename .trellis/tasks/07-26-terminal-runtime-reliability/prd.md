# 终端输入与后台运行可靠性

## Goal

终端输入始终优先、窗口最小化不拖停任务、ThreadTerm 退出后不留下由它管理的子进程。

## Requirements

- 手机按键不得等待操作记录写入完成。
- 操作记录按顺序后台写入；队列满、写入失败和退出前未写完必须有计数和日志。
- 记录中继续只保存元数据，不保存用户输入内容。
- 同一终端的输入顺序必须严格保持，不因后台化而乱序。
- 输入管道暂时阻塞时，不得占满整个后台执行线程池。
- 主窗口被冻结或最小化时，过期界面不得永久阻止 PTY 继续读取。
- 重新打开窗口后必须通过快照恢复，而不是依赖过期界面的未处理队列。
- ThreadTerm 管理的 app-server、命令包装进程及其子进程在应用退出时全部结束。

## Acceptance Criteria

- [ ] 数据库人为锁住 5 秒时，手机按键仍在 100 ms 内进入终端。
- [ ] 1000 条连续输入顺序完全一致。
- [ ] 日志失败不泄露输入内容，并能看到失败数量。
- [ ] 最小化运行持续输出任务 10 分钟不停止。
- [ ] 恢复窗口后终端画面与真实状态一致。
- [ ] 退出 ThreadTerm 后不存在受管的残留 AI/包装进程。
