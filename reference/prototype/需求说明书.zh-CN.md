# ThreadTerm 产品需求说明书

> 评审稿 · 2026-09-08 · 面向产品决策与后续重构

ThreadTerm 让同时使用多个本地终端和 AI 工具的人，把项目目录、会话、待处理事项和可恢复的工作上下文放在一个地方。本文只说明用户应得到的体验和结果，不规定技术方案、接口或底层存储实现；用户仍可选择自己的工作目录和数据位置。

## 阅读方式

- 先读边界、状态口径和术语，再按自己的场景读 25 组需求。
- `现状`是本次静态审阅所见，不能替代实际运行验证。
- `保留目标`表示不因原型缺席而取消，不表示已承诺某版本或上线时间。
- 未定的形态、范围、顺序和价格集中在[待决问题](#待决问题)，正文不暗中替其中任一方案作决定。

## 产品边界、状态与术语

本说明覆盖桌面工作、项目目录和工作树、终端和 AI、恢复与提醒、工作区和文件、预设、用量、设置与数据、移动访问，以及其他工具调用 ThreadTerm 终端的能力。VS Code 扩展及其专属实验线不在本次范围内；这不判断其去留。

| 标记 | 含义 |
| --- | --- |
| 已接入 | 主应用中查到用户能力；本次未运行验证。 |
| 部分接通 | 有流程或界面，但边界、平台或闭环未完成。 |
| 仅原型 | 原型可演示，不能视为真实功能已交付。 |
| 保留目标 | 后续应保留或补齐，具体范围仍待评审。 |

| 术语 | 面向用户的意思 |
| --- | --- |
| 项目/工作目录 | 一组在同一目录下开展的工作；普通目录也可使用，并非只能是 Git 项目。 |
| 分支/工作树 | 分支是同一项目的一条独立开发线路；工作树是它对应的可单独工作的目录和上下文，目录缺失时历史仍可能可读。 |
| 会话/终端 | 一次普通命令终端或 AI 命令行工具工作的入口及其输出、输入和状态。 |
| 图形聊天 | 内置对话界面；当前仅查到两种，不等同于所有 AI 命令行工具都有。 |
| 历史 | 已结束、归档或从本机发现的记录；可看不必然可继续运行。 |
| 待处理 | 需要用户注意或回到上下文判断的事项；它不自动批准或执行。 |
| Git 差异 | 目录中相对已记录版本的文件改动，用于帮助审阅，不等同于提交或发布。 |
| 暂存、未暂存、未跟踪 | 分别指已选入下一次版本记录的改动、尚未选入的改动，以及还没交给 Git 管理的文件。 |
| Token | AI 服务计量文本处理量的单位；费用和数量可能是估算或未知。 |

**关键区别。** 阅读不等于批准；“已读”“已处理”“忽略”均不能批准 AI 请求或执行命令。隐藏/收起视图只改变显示；关闭文件或一般视图只关闭显示，关闭终端标签可在明确说明并确认后结束进程；结束会话是停止进程而不只是停止输入；归档保留快照。移除工作树是否删除目录必须先明确范围，历史不能静默丢弃。关注是重点清单、快捷固定是快速选择入口、书签是回访标记、待处理是事件队列，四者相互独立。设置导出只是设置，不是完整备份。

## REQ-01 初次使用与开始工作

**目的。** 让用户能从新工作、最近工作或待处理事项进入合适的下一步。

**动作与结果。** 首次进入有简短引导、开始新会话、继续最近会话和待处理摘要；开始描述只作为创建时的预填意图，不会未经确认执行命令。

**规则与状态。** 可取消创建；无继续项、待处理或最近记录时应有明确空态。原型的离线演示限制不能写成正式产品永久限制。现状：创建和快捷入口已接入，开始页流程仅原型演示。

**验收。** [AC-01](#ac-01)、[AC-02](#ac-02)。

<a id="req-02"></a>
## REQ-02 项目与工作目录

**目的。** 用户能从自己的目录开始，不因目录不是 Git 仓库失去终端、文件和工作区能力。

**动作与结果。** 用户选择或输入目录、命名会话、选择工具和可选启动内容后，工作归属清晰显示；项目列表帮助回到已有目录。读取失败与真正空目录必须有不同提示和下一步。

**规则与状态。** 当前项目主要按现有终端目录聚合，不承诺完整的独立空项目管理。终端内部切换目录不应悄悄改变文件浏览和草稿所属。现状：已接入；空项目管理待评审。

**验收。** [AC-03](#ac-03)、[AC-04](#ac-04)。

<a id="req-03"></a>
## REQ-03 工作树管理与目录恢复

**目的。** 用户能看清工作树和可用性，在目录丢失时不把旧上下文误当作可继续工作。

**动作与结果。** 用户可浏览工作树与分支、进入已有树并在适用时创建终端；目录缺失时可读关联记录、重新定位或查看恢复选项。移除前应显示影响和阻塞原因。

**规则与状态。** 当前可识别已有工作树、分支并从既有分支创建工作树后开终端；原型的新建、移除、重新定位是模拟。重新定位不得自动启动旧会话；缺目录、已结束与归档不可混同。移除时是否删除实际目录、怎样保护历史和怎样恢复，均须由 [Q-03](#q-03) 定义。

**验收。** [AC-05](#ac-05)、[AC-06](#ac-06)。

<a id="req-04"></a>
## REQ-04 项目与分支概览

**目的。** 用户不进入每个终端也能理解项目或工作树的活动、关注、最近记录和可用用量。

**动作与结果。** 项目、工作树和会话有不串线的导航：项目进入项目概览，工作树进入分支概览，会话进入工作区。概览固定展示关注、进行中和最近记录三个区域，空态仍保留区域和下一步提示；用户可从项目和工作树展开相应用量。项目固定和排序只影响快速访问。

**规则与状态。** 概览不是第二个资源管理器；关注和待处理不能混为同一列表。固定数量和原型合成图表不是产品上限或真实统计。现有项目列表、固定项目入口和工作区主页已接通；独立的项目页、分支页布局及其用量视图仅原型。空项目的保留、重命名和移除见 [Q-08](#q-08)。

**验收。** [AC-07](#ac-07)、[AC-42](#ac-42)。

<a id="req-05"></a>
## REQ-05 创建与配置终端

**目的。** 用户可清楚创建、命名和调整会话，并理解一次性任务与持续交互的区别。

**动作与结果。** 用户选择目录、名称、工具和可选启动内容；有命令时可选择交互工作或执行后退出。可改名、复制目录、打开目录并编辑配置；配置可仅保存供下次重启生效，或在明确中断影响后保存并立即重启。

**规则与状态。** 支持 Shell、Claude、Codex、OpenCode、Gemini、Kimi、Grok 及常见命令预设。六类 AI 命令行工具不等同于图形聊天。评审、修复、调研、测试、文档等用途标签只记录意图，不自动做任务。现状：已接入。

**验收。** [AC-08](#ac-08)、[AC-09](#ac-09)、[AC-43](#ac-43)。

<a id="req-06"></a>
## REQ-06 运行、结束、归档与重试

**目的。** 用户能判断会话是否可输入、完成、失败、等待、结束或仅可查看，并安全处理异常。

**动作与结果。** 用户可再次运行适用任务、设置或取消自动重启、结束会话，或归档并找回快照。自动重启显示次数、倒计时、近期记录和上限。结束会停止目标进程，结束失败、等待或需重试时应显示状态和可选下一步；适用的强制结束必须明确目标、意图和后果。结束后仍能阅读输出和历史。

**规则与状态。** 运行、等待、任务完成、进程退出、结束、可恢复和目录缺失必须分别表达。自动重启的现有次数选项不是永久限制，关闭后待执行重启要取消并保持状态可辨；AI 命令行工具完成判断可能有兼容辅助规则，不承诺绝对准确。归档不是删除或完整备份。现状：已接入。

**验收。** [AC-10](#ac-10)、[AC-11](#ac-11)、[AC-44](#ac-44)。

<a id="req-07"></a>
## REQ-07 AI 工具与图形对话

**目的。** 用户选择合适的 AI 工作方式，能分清不同工具、历史和界面各自支持什么。

**动作与结果。** 用户可启动适用 AI 命令行工具，选择本机 AI 历史恢复，并在支持时用图形聊天发送和阅读回复；适用的 AI 会话可导出为便于阅读的 Markdown 文件。恢复前验证目标可交互；失败时保留原目标并说明原因。v3 交互原型不提供该导出入口，见[功能对照 F-125](./功能对照与审阅记录.zh-CN.md)。

**规则与状态。** 当前查到六类 AI 命令行工具，图形聊天只接入 Codex 和 Claude 两种；不承诺六类都有图形聊天，也不承诺通用账户或密钥管理页。不同工具历史发现与命令行恢复相近但不同。现状：命令行工具已接入，图形聊天两种已接入。

**验收。** [AC-12](#ac-12)、[AC-13](#ac-13)、[AC-43](#ac-43)。

<a id="req-08"></a>
## REQ-08 历史查找与恢复

**目的。** 用户被打断或隔天回来时能找到过去工作，并知道记录是否可继续。

**动作与结果。** 用户可按范围、项目、工作树、关键词和 AI 工具查找记录，看到扫描进度、失败原因、重试和导入入口；可从归档或通知回到准确目标。

**规则与状态。** 历史阅读、归档找回和不同 AI 工具的本机历史发现分别保留；普通命令终端不适用 AI 工具会话恢复。原型“继续上次”使用固定示例或第一个可用会话，并不代表实际最后工作位置；原型历史只回到所有终端并高亮，尚未形成完整闭环。入口形态见 [Q-01](#q-01)。

**验收。** [AC-14](#ac-14)、[AC-15](#ac-15)。

<a id="req-09"></a>
## REQ-09 所有终端与查找组织

**目的。** 用户能在大量会话中找到正确对象、保留返回路径，并避免误判搜索能力。

**动作与结果。** 用户可按项目、工作树、状态和关键词组织终端，切换卡片或列表，用命令面板创建、跳转、查看意图或打开设置，并通过近期会话返回。项目内可以整理顺序。

**规则与状态。** 当前卡片搜索针对名称、项目、状态等会话信息，不能承诺实时终端全文搜索；历史找回可检索的输出摘要是另一能力。状态变化不应让进行中的会话无故消失。现有网格、焦点/全屏、命令面板和近期入口已接入；原型还提供卡片/列表切换和新的筛选组合。主窗口内浮层可平铺或轮播选择会话，见 [REQ-14](#req-14)。原型清除筛选后需重新打开是演示局限，不是未来体验目标。

**验收。** [AC-16](#ac-16)。

<a id="req-10"></a>
## REQ-10 关注、快捷固定与书签

**目的。** 用户以不同方式减少寻找成本，而不让一个动作改变另一个清单。

**动作与结果。** 用户可关注会话、快捷固定常用卡片、为历史或上下文加书签，并可独立取消。添加关注支持预览、多选和取消；显示名变更应在关联入口同步。

**规则与状态。** 关注是重点清单，快捷固定是快速选择入口，书签是回访标记，待处理是事件队列。快捷固定最多六张卡是现状，不是未来上限。当前关注和快捷固定入口已接入；书签仅原型，原型“书签免费”也不是正式权益结论。

**验收。** [AC-17](#ac-17)、[AC-18](#ac-18)。

<a id="req-11"></a>
## REQ-11 待处理、通知与监督提醒

**目的。** 用户在等待输入、失败、完成、新回复或重试受限时得到可追溯且不越权的提醒。

**动作与结果。** 用户可查看详情、打开准确会话、标记已读、按会话清理、忽略或标为已处理；可调整系统通知、应用内提示和监督提醒。

**规则与状态。** 待处理详情当前可读但不在详情中执行实际操作；已读、已处理、忽略只能整理提醒，打开关联终端可自动确认该提醒已被查看，但不能批准 AI 请求或执行命令。监督提醒默认关闭，当前只观察已固定的终端；停滞提示应与失败、必须处理事项分开。通知中心打开时避免重复浮动提示。现有待处理、通知与监督提醒已接入；原型停滞规则是独立的演示流程，其后续形态需评审。

**验收。** [AC-19](#ac-19)、[AC-20](#ac-20)。

<a id="req-12"></a>
## REQ-12 工作区、标签与导航返回

**目的。** 用户在同一目录中切换会话、文件和改动时知道位置，并安全返回来源。

**动作与结果。** 工作区提供会话、文件和改动标签，可拖动、关闭当前、其他或全部；关闭终端标签时，用户可选“仅关闭标签”或“关闭并结束”，前者保留进程，后者才进入结束流程。从通知、项目、独立的“所有终端”主页面或预设进入后能返回合理来源；错误时可重试。

**规则与状态。** 关闭文件或一般视图不等于结束终端；终端关闭确认必须同时保留“仅关闭标签”和“关闭并结束”。结束失败时不得关闭上下文；超时要明确进程仍在运行，并允许继续等待、保留标签或明确选择强制结束。未保存文件、差异与草稿继续提供保存、放弃和取消，外部修改冲突需明确展示。现有工作区标签和关闭保护已接入；新概览、预设入口及其返回路径是保留目标。

**验收。** [AC-21](#ac-21)、[AC-22](#ac-22)。

<a id="req-13"></a>
## REQ-13 并排与布局

**目的。** 用户对照多个会话或工作树的上下文，同时控制复杂度和误操作风险。

**动作与结果。** 普通工作区可在同一工作树中添加、替换、排序和关闭并排会话，并标出当前焦点；预设在确认后可展现多工作树布局。

**规则与状态。** 原型普通并排限同工作树、最多四格；预设可跨树。这是两个场景，不能写成全面禁止跨树并排；上限与未来范围仍待评审，见 [Q-02](#q-02)。

**验收。** [AC-23](#ac-23)、[AC-24](#ac-24)。

<a id="req-14"></a>
## REQ-14 快捷选择与浮动终端

**目的。** 用户短暂切换、查看或输入另一会话时，不丢失主工作位置。

**动作与结果。** 用户可用选择器、快捷键、近期会话或浮动终端快速找到会话；浮动终端可收起并恢复，适用时可独立窗口或主窗口内展示。

**规则与状态。** 收起不结束会话；主窗口内浮层和独立置顶窗口不同。轻量模式禁用独立浮层时说明原因并保留其他路径。原型“置顶”只是页面演示，不能否定现有浮动终端。现状：已接入。

**验收。** [AC-25](#ac-25)。

<a id="req-15"></a>
## REQ-15 终端输入与输出阅读

**目的。** 用户可靠阅读长输出、复制粘贴和回到底部，并在异常时保留上下文。

**动作与结果。** 用户可选择、复制粘贴和上滚阅读；读旧输出时，新输出只提示数量，用户可主动回到底部。退出后保留输出，重连、重启或登录问题有重试和说明。

**规则与状态。** 输入草稿、已发送内容和输出分别保护；结束或缺目录会话应只读。当前未查到块级解释、实时全文检索、广播输入、字体缩放等能力，本轮不承诺。现状：已接入。

**验收。** [AC-26](#ac-26)。

<a id="req-16"></a>
## REQ-16 文件、草稿与预览

**目的。** 用户在工作区查看和编辑文本时不丢草稿，并知道预览对应哪个版本。

**动作与结果。** 用户可逐级浏览目录、打开文本、编辑保存，并查看适用的 Markdown 或 HTML 预览；关闭有修改文件时可保存、放弃或取消；同步失败与磁盘冲突保留输入并给出处理说明。

**规则与状态。** 当前不编辑超过约 1MB 的文本或二进制文件，这是现有限制，不是永久阈值。相对资源只在工作区范围解析；依赖服务的网页需用户明确预览地址；预览不必等同未保存草稿。现状：已接入，原型内存草稿仅演示。

**验收。** [AC-27](#ac-27)、[AC-28](#ac-28)。

<a id="req-17"></a>
## REQ-17 文件改动查看与编辑

**目的。** 用户理解目录的改动状态，审阅文本差异，并以可解释方式编辑适用一侧。

**动作与结果。** 用户可查看暂存、未暂存和未跟踪改动，阅读文本差异，在允许一侧编辑并按行或块还原后保存。大文件、二进制、读取失败或只读侧都说明原因。

**规则与状态。** 已查到改动查看、文本对比和未暂存侧编辑；未查到完整图形化提交、推送、拉取或合并入口，不能作为现有承诺。原型差异是合成演示。现状：已接入。

## REQ-18 工作预设

**目的。** 用户把重复准备保存为可复用上下文，并在恢复前掌握目录、会话、布局和待审阅命令。

**动作与结果。** 用户可创建、预览、选择和恢复预设；预览展示可用与不可用工作树、会话和命令。确认后进入布局，仍可退出预设回普通工作区。

**规则与状态。** 打开或确认恢复预设均不自动执行保存的命令；这些命令进入待审阅清单，由用户对目标会话明确发起执行。恢复不覆盖草稿或未发送输入。原型命令和授权切换只是演示；是否允许逐项确认后启动会话，以及失效目标处理，见 [Q-04](#q-04)。保存会话预设暂无真实实现证据，现状：仅原型。

**验收。** [AC-30](#ac-30)、[AC-31](#ac-31)。

## REQ-19 用量与费用

**动作与结果。** 用户可查看今日、七天、三十天或全部范围，筛选项目、AI 工具、模型、成败和来源，阅读趋势、拆分与明细。无可靠数据或未定价时显示未知。

## REQ-22 移动访问与跨设备工作

## 待决问题

<a id="q-01"></a>
### Q-01 历史入口

选择 A：在“所有终端”中提供历史筛选、阅读和恢复闭环；选择 B：增加独立历史入口。两者均须保留搜索、阅读和恢复状态区分；原型没有独立页不是决定依据。

<a id="q-02"></a>
### Q-02 普通并排范围与规模

选择 A：普通并排继续限同一工作树；选择 B：扩展为有明确边界的跨树并排。预设多工作树布局是独立场景；四格只是原型当前值。

<a id="q-03"></a>
### Q-03 工作树真实操作范围

需决定首轮覆盖已有分支创建、空树创建、移除、重新定位和冲突处理中的哪些流程。尤其要明确“移除”是仅从应用移除，还是清理实际工作目录，以及运行会话、未保存修改和历史记录怎样保护、恢复；两种操作不能共用含糊确认。原型模拟不等于已完成。

<a id="q-04"></a>
### Q-04 预设恢复的执行边界

需决定是否只恢复视图和待审阅命令，还是在逐项确认后可启动会话；也需决定失效目标的提示、跳过和后续恢复方式。

<a id="q-05"></a>
### Q-05 完整备份与数据保留

需定义完整备份是否提供、包含哪些数据、导入怎样避免覆盖，以及保留、容量和迁移后清理政策。当前设置导出不能承担该定义。

<a id="q-06"></a>
### Q-06 移动范围与平台顺序

需决定移动端首轮重构以现有浏览器终端访问为基础，还是同时接通安全工作区、共享标签、文件、差异和编辑权，并明确各平台范围。

<a id="q-07"></a>
### Q-07 商业形态与权益

需决定哪些本地增强构成付费价值、价格和许可、更新权益及免费能力边界。原型数额、一次买断和期限均未获批准，首轮交付顺序另见 [Q-10](#q-10)。

### Q-08 空项目生命周期
