# OpenWork Desktop - Desktop GUI Application

## Project Overview

Transform the existing OpenWork web application into a native desktop GUI application using Electron. The goal is to remove authentication/registration and create an "open-and-use" experience.

## Target Platform

- **Primary**: macOS (x64, arm64) - Intel & Apple Silicon
- **Primary**: Windows (x64) - Windows 10/11
- **Secondary**: Linux (x64)

### Cross-Platform Requirements (平台无关性)

All code must be platform-agnostic and work identically on macOS and Windows:

#### File Path Handling
- **ALWAYS** use Node.js `path` module for path operations
- **NEVER** hardcode forward/backward slashes
- Use `path.join()`, `path.resolve()`, `path.sep`
- Store paths in platform-neutral format (forward slashes) in database

```javascript
// WRONG
const filePath = folder + '/' + filename;

// CORRECT
const path = require('path');
const filePath = path.join(folder, filename);
```

#### Environment Variables
- Use `process.env` consistently across platforms
- Use `path.delimiter` for PATH separators (`:` on Unix, `;` on Windows)
- Use `os.homedir()` for home directory resolution

#### Shell Commands
- Use `os.platform()` to detect platform when necessary
- Windows: Use `cmd.exe` or PowerShell for shell commands
- macOS/Linux: Use `bash` or `sh`
- For file operations, prefer Node.js `fs` API over shell commands

#### Native Modules Compilation
All native modules must provide prebuilt binaries for both platforms:
- **node-pty**: Prebuild for darwin-x64, darwin-arm64, win32-x64
- **better-sqlite3**: Prebuild for all target platforms
- Use `electron-rebuild` in postinstall script

#### Platform-Specific Behaviors
| Feature | macOS | Windows |
|---------|-------|---------|
| App Menu | Top menu bar | Window menu |
| Shortcuts | Cmd+Key | Ctrl+Key |
| Window Controls | Left side | Right side |
| Tray Icon | Template icon | Regular icon |
| File Dialog | Native macOS dialog | Native Windows dialog |
| Update Mechanism | dmg + zip | nsis installer |

## Key Changes from Web Version

### 1. Authentication Removal
- Remove LoginForm component
- Remove SetupForm component (first-time registration)
- Remove ProtectedRoute wrapper (direct access to AppContent)
- Simplify AuthContext to always return authenticated state
- Remove auth-related API routes from backend
- Remove user database tables (users, sessions)
- Keep git configuration flow (part of Onboarding)

### 2. Simplified Onboarding
- Skip login/registration screens
- Only show Git Configuration step (optional)
- Show CLI Authentication step (Claude Code, Cursor, Codex)
- Make all onboarding steps skippable

### 3. Desktop Integration
- Native window management (minimize, maximize, close)
- System tray integration (optional)
- Native file dialogs for project selection
- Desktop notifications
- Auto-update functionality
- Keyboard shortcuts (Cmd/Ctrl+Q to quit, etc.)

### 4. Single Executable
- Bundle frontend and backend into one app
- Auto-start backend server on app launch
- Load frontend from local server (or file://)
- Graceful shutdown handling

## Risk Assessment

1. **node-pty compatibility**: Native module may need recompilation for Electron
   - **Mitigation**: Use electron-rebuild, provide prebuilt binaries
2. **better-sqlite3**: Similar native module concerns
   - **Mitigation**: Same as node-pty
3. **Cross-platform path handling**: Windows vs Unix path differences
   - **Mitigation**: Strict use of path module, comprehensive testing
4. **Auto-update**: Requires code signing certificates (macOS notarization, Windows cert)
   - **Mitigation**: Start with manual updates, add auto-update later
5. **Large bundle size**: May need optimization
   - **Mitigation**: Exclude dev dependencies, use asar packaging
6. **Platform-specific CLI discovery**: Different paths for Claude Code/Cursor on macOS vs Windows
   - **Mitigation**: Platform-specific detection logic in server

## CLI Discovery (Platform-Specific)

### macOS
- Look in: `/usr/local/bin`, `/opt/homebrew/bin`, `~/.local/bin`
- Commands: `claude`, `cursor`, `codex`

### Windows
- Look in: `%LOCALAPPDATA%\Programs\cursor\resources\app\bin`
- Look in: `%APPDATA%\npm` (for global npm packages)
- Commands: `claude.cmd`, `cursor.exe`, `codex.cmd`
